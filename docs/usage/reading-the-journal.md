# Reading the journal

## The repository

```php
use OiLab\OiLaravelChangelogs\Services\ChangeLogRepository;

public function __construct(private readonly ChangeLogRepository $changeLogs) {}
```

| Method | Answers |
| --- | --- |
| `all()` | `Collection<ChangeLogEntry>`, newest first |
| `paginate($perPage, $page, $path)` | `LengthAwarePaginator<ChangeLogRowData>` |
| `find($slug)` | `?ChangeLogEntry` |
| `detail($entry)` | `ChangeLogEntryData` |
| `adjacent($slug)` | `['previous' => ?ChangeLogRowData, 'next' => ?ChangeLogRowData]` |
| `pageOf($entry, $perPage)` | the page of the list the entry sits on |
| `path()` | the absolute change log directory |

Ties on the date are broken by the slug, descending, so two entries written the
same day keep a stable order from one read to the next — which is what the
previous and next buttons walk along. "Previous" is the row **above**: the
newer entry. The buttons walk the list the reader is looking at, not the
calendar.

## Two shapes, not one

`ChangeLogRowData` is what the list column draws: slug, title, date, type and
its label, tags, commits, and the opening paragraph. There may be a hundred of
them on a page.

`ChangeLogEntryData` is the entry being read. It carries everything a row does
plus its content, and exactly one of `html` and `markdown` is ever filled —
whichever the configured engine asked for. Sending the whole journal rendered
to draw a column 24rem wide is the thing this split makes unwritable.

Both are `spatie/laravel-data` objects, so `oi-laravel-ts` generates the
TypeScript interfaces from them.

## The cache

The whole directory is parsed to draw one page of the list — there is no index
to query — so the parse is cached under a fingerprint of the directory: every
markdown file's name and modification time. A file added, edited or removed
changes the fingerprint and the next read rebuilds.

Nothing has to be regenerated by hand, and nothing is held between requests:
the cache is the application's, not a property, so an Octane worker that served
yesterday's journal does not keep serving it.

## The two routes

| Name | URL | Answers |
| --- | --- | --- |
| `change-logs.index` | `/change-logs` | the screen, opened on the first entry of the page |
| `change-logs.show` | `/change-logs/{slug}` | json to a fetch, the whole screen to a visit |

`show` is two answers behind one URL. The page swaps its right-hand pane with a
fetch asking for `application/json`, so the column keeps its scroll; an Inertia
visit and a browser opening the link cold both get the whole screen. The pane
the reader swaps and the page a pasted link opens therefore cannot drift apart.

The slug is constrained to `[a-z0-9\-]+`, which is a file name and nothing that
could walk out of the directory.

## Declaring your own routes

Set `route.enabled` to `false` and point your own at the controller — inside an
authenticated console group, for instance:

```php
use OiLab\OiLaravelChangelogs\Http\Controllers\ChangeLogController;

Route::middleware(['web', 'auth', 'can:administer'])
    ->prefix('console')
    ->name('console.')
    ->group(function () {
        Route::get('change-logs', [ChangeLogController::class, 'index'])->name('change-logs.index');
        Route::get('change-logs/{slug}', [ChangeLogController::class, 'show'])
            ->where('slug', '[a-z0-9\-]+')
            ->name('change-logs.show');
    });
```

Set `route.name` to `console.change-logs.` to match, since the controller
builds the paginator's links from `route.name`.
